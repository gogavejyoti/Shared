Step-by-step explanation
 1. Start with the original list  
evalList = a means behavior is unchanged if ordering cannot be computed.
 2. Check dependency index support  
The new ordering only runs when _dependencyTryBuildGraph and _dependencyIndexEnabled() are available.
 3. Build execSet from calcChain cells  
Only cells that actually contain formulas are passed into the dependency graph; blank cells are skipped.
 4. Build a lean dependency graph  
recomputeAllOnEmpty: false prevents a full-sheet fallback; lean: true avoids heavy group payload generation.
 5. Map graph keys back to cell objects  
keyToCell converts "r{r}c{c}i{sheetIndex}" keys back into the {r, c, index} objects used by the existing recalc loop.
 6. Topologically order impacted cells  
visit(root) walks graph.parentKeysOf(root) first, so dependencies are pushed into ordered before their dependents. That is what fixes E95 being evaluated before E11.
 7. Use an iterative stack, not recursion  
Large workbooks can have long dependency chains; the stack avoids call-stack overflow. onStack prevents cycles from looping forever.
 8. Append non-indexed cells  
Any calcChain cell not present in the graph is appended in original order, so no formula is dropped.
 9. Fallback on error  
catch restores evalList = a, so the change cannot break the path if graph APIs behave unexpectedly.
10. Existing evaluation body untouched  
   Only iteration order changed; formula parsing and formula.execfunction(...) logic are unchanged.
